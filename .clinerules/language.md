# 回答言語

**すべての回答を日本語で書く。** コード中の識別子やコミットメッセージは英語のままにする。

- ユーザーへの説明、報告、確認、質問はすべて日本語
- コード内のコメントも日本語を既定とする（既存の `app.js` / `styles.css` /
  `tools\*.ps1` は日本語コメントで統一されている）
- **日本語の文に他言語の語句を混ぜない。** 中国語・韓国語・英語の語が
  文中に紛れ込んだ文章は、書き直す。
- `.ps1` は Windows PowerShell 5.1 が BOM なしファイルを ANSI と誤読して日本語が壊れる。
  スクリプト内で日本語リテラルを使う場合は、リポジトリ既存の `tools\*.ps1` と同じく
  コードポイントから組み立てる（`function U { param([string]$hex) ... }`）。

## 送信前に必ず確かめる

この手順を守らないと、日本語以外の語句が混入したまま回答が出る。編集ツールは
特定の漢字を別の字に変えたり落としたりすることが実際に起きている。

**長い回答や、ファイルに日本語を書くときは、次の順番を守る。**

1. まず文章を組み立てる
2. **書き込む**（ファイルの場合はそのまま、回答の場合は一時ファイルに書く）
3. **読み返して確認する**（`read_files` で読み、中身を見る）
4. 混入があれば直してから送り出す

省略すると検査が働かない。この環境では実際にこれで混入を検出できた。

### 検査で見つかる例

- 漢字が別の漢字に変わる（機械 → 機検、共用 → 共）
- 中国語の助詞が混ざる（成長の途中 → 成長**的**）
- 単語が差し替わる（繰り返し適用 → **Repeated** 適用）

これらは目視でしか気づけない。機械検出は下の方を参照。

## 機械で検出できる範囲

```powershell
powershell -ExecutionPolicy Bypass -File tools\scan-stray-characters.ps1
```

リポジトリ全体を走査して次を検出する（検出があれば終了コード 1）。

- 韓国語（ハングル。日本語と文字ブロックが重ならない）
- 漢字の部首・康熙字典・囲み文字・かっこ囲み英数字
- 文字化け跡（`U+FFFD`）

**検出できないもの**：中国語と日本語が同じ字を使う語（`的`、`時`、`如` など）。
正しい日本語にも現れるので、機械的な判定はできない。上の「読み返す」が頼り。

## ファイルを変更したとき

- **書き終えたら `git diff` を読む。** 意図した行だけが変わっているか確かめる。
  編集ツールは無関係な行を書き換えることがある（実際に起きている）。
- ファイルの中身を `read_files` で読み返して、文字化けしていないか確かめる。
- 変更したファイルが意図と違っていた場合は、`git checkout -- <file>` で戻す。
   部分的に直そうとすると、さらに別の箇所を壊すことが多い。

## 実装にあたって

- **推測を事実として書かない。** 検証していない計算式やデータ構造は、実データで確認してから書く。
  確認できなかったものは、その旨を明示する。
- **データに無いものを表示しない。** 値を推測で埋めた表は利用者の判断を誤らせる。
  計算できないなら「その値がデータに無い」と書く。
- 既存の規約に従う。CSS は共通ルールへ追加して重複定義を避ける。
  表のヘッダを `position: sticky` で固定するなら背景は不透明にする。
- **大きなファイルへの編集は慎重に行う。** 局所的な修正を繰り返すと、無関係な箇所を
  壊しやすくなる。まとめて書き直すか、影響が小さい変更に分ける。
